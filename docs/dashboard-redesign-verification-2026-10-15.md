# Responsive dashboard — 15 October 2026

The owner explicitly selected **Implement missing changes** for the supplied responsive-dashboard brief. This implements that scope in the existing Money Nest app. Financial records, backend routes, authentication policies, selectors, and account classifications are unchanged.

## Resulting behavior

- Phone dashboard: existing M/wordmark branding, working Search and Notifications routes, local-time greeting using an authenticated first name, compact NestBot entry, month picker, four financial cards, recent transactions and bills. Home / Accounts / center Add / Analytics / Profile replaces the former bottom bar. Profile exposes existing finance routes so removing More and the dashboard shortcut strip does not orphan them. Existing Orders visibility rules remain intact.
- Desktop: existing sidebar and routes, greeting/NestBot, Search/Notifications, one header Add button, compact bank card beside stacked spending and debt cards, then bills/recent transactions. The old Overview/welcome heading and shortcut strip are removed.
- Bank details use `dashboardMetrics` and `accountBalance`, with active bank accounts only, masked suffixes, individual reporting baselines/current cutoff dates, and unknown reports explicitly excluded. Aggregate partial coverage is in the card's accessible description. A calculation cutoff uses today's actual selector cutoff, not the oldest individual report date. Historical month selection does not relabel current balances as historical balances.
- Spending details use `monthlySummary`, `spendingByCategory`, and the same posted selected-month expense policy as the card. Gross spending, matched refunds and net are labeled separately. Transfers, repayments, pending and voided records do not become posted expenses. View all retains the provider's selected month and opens the expense filter in the existing transaction history.
- Credit and Pay Later details use `usageSummary`, `latestSnapshot` and `billSummary`. Usage and reported outstanding are separate; unknown limits and partial bill-only exposure never become exact utilization/available-credit totals. Stored dues, statements, collateral links and Pay Later repayments link to existing account/bill pages.
- One shared Radix details dialog traps focus, locks background scrolling, supports close/backdrop/Escape dismissal and restores the opening card. It is a bottom sheet at the existing 760px mobile breakpoint and a centered modal above it. The dependency has no built-in swipe dismissal.
- Greeting uses a hydration-safe external-store clock, explicit valid profile time zone or browser fallback, minute-boundary refresh, foreground refresh and listener/timer cleanup. No geolocation is requested.

## Practical limits

NestBot has no chat backend: its panel explicitly says unavailable and sends no financial data to an AI service. Receipt/order extraction is a different existing feature. Missing fields show Not available/Not reported/Not set. No new theme is invented: the app currently ships a light token palette without an active dark-mode setting, and new surfaces reuse those tokens. Browser checks cannot certify physical iOS safe-area behavior, actual 200% browser zoom, live cloud persistence, email recovery/confirmation, bank synchronization, notifications delivery or AI extraction. Those services are outside this presentation change.

No financial rows, reported balances, imports, cloud profile transfers, migrations or production credentials were changed during this implementation. Synthetic screenshots are verification artifacts, not owner financial records.
